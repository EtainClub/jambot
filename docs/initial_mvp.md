# 잼통 기반 인스타그램 AI 팩트체크 MVP 설계

설계 기준: 2026년 10월 8일

제안하는 서비스는 잼통의 근거 자료를 활용해 인스타그램의 정책 관련 주장을 검증하고, 여러 관리자가 팩트체크 댓글을 분담해서 게시하는 협업 플랫폼입니다.

### 가장 중요한 설계 원칙

잼통을 기준 정보로 사용하되, 잼통에 없는 정부 정책을 AI가 임의로 사실이라고 판단해서는 안 됩니다.

검증 자료를 두 계층으로 구성합니다.

- 1차: 잼통 지식베이스 — 저장소의 주장, 근거, 출처, 시점, 관련 업적을 검색합니다.
- 2차: 최신 공식 자료 — 잼통에 없는 정책이나 변경된 정책은 정부 부처·법령·공식 공고에서 확인합니다.

잼통 자료와 최신 공식 자료가 충돌한다면 조용히 한쪽을 선택하지 않고, 변경 시점과 충돌 내용을 관리자에게 보여줍니다.

## 2. MVP의 핵심 범위 확정

A. 해시태그 자동 탐색

관리자가 등록한 정책 관련 해시태그를 주기적으로 검색

B. 지정 계정 모니터링

관리자가 지정한 공개 전문 계정의 신규 게시물 확인

C. 인스타그램 게시물 제보

게시물 링크, 텍스트, 스크린샷으로 검증 요청

이 세 경로에서 들어온 게시물은 하나의 Firestore 작업 큐로 합쳐집니다. 이후 AI 팩트체크 → 댓글 초안 생성 → 관리자 배정 → 푸시 알림 → 수동 댓글 게시라는 공통 과정을 거칩니다.

MVP에서는 Instagram API를 통한 댓글 작성은 구현하지 않습니다.

## 3. 세 가지 수집 엔진의 상세 설계

### A. 해시태그 탐색 엔진

첫 버전은 6개 해시태그부터 시작합니다.

MVP 기본 해시태그

6개 활성화

#정부정책

#지원금

#민생정책

#청년정책

#연금

#부동산정책

 활성 해시태그 설정 복사초기 설정을 선택하는 예시입니다. 실제 Firestore 설정에는 아직 연결되지 않았습니다.

수집 처리 과정

1. Cloud Scheduler가 설정된 주기로 수집 작업을 실행합니다.
2. 활성 해시태그의 ID를 조회하거나 캐시에서 가져옵니다.
3. `recent_media`로 공개 게시물 정보를 조회합니다.
4. 게시물 ID로 중복 여부를 확인합니다.
5. 정책 관련 주장 포함 여부를 가볍게 분류합니다.
6. 검증할 가치가 있는 게시물만 AI 정밀 분석 큐에 넣습니다.

해시태그 검색에는 최근 미디어·인기 미디어 조회 기능이 있지만 결과가 전체 게시물의 완전한 목록은 아닙니다. 7일 내 서로 다른 해시태그 30개 제한을 관리해야 하며, 공개 콘텐츠 검색 기능에 대한 Meta 심사도 실제 계정에서 확인해야 합니다.

관리자 화면에서 인스타그램 사용자명을 등록합니다.

### C. 인스타그램 게시물 제보

이 경로는 가장 먼저 완성해야 할 기능입니다. Meta의 공개 콘텐츠 검색 권한을 아직 받지 못한 상황에서도 운영할 수 있기 때문입니다.

게시물 제보 화면

인스타그램 게시물 URL

검증할 주장 (선택)

 AI 검증 요청 예시

위 입력은 대화 내 기능 예시이며, 실제 앱의 제보 DB에는 저장되지 않습니다.

실제 웹앱에서는 추가로 스크린샷 첨부, 제보자 메모, 동일 URL 제보 자동 병합, 처리 결과 확인 기능을 제공합니다.

PWA의 `share_target`을 설정하면 지원하는 Android 브라우저에서 설치된 웹앱을 시스템 공유 메뉴의 대상으로 등록할 수 있습니다. 다만 인스타그램 앱이 전달하는 정보와 모바일 운영체제의 지원 범위에 따라 동작이 달라지므로 URL 붙여넣기를 기본 경로, 시스템 공유를 편의 기능으로 설계합니다.

## 4. 여러 관리자 협업 설계

여러 명이 함께 운영한다면 가장 중요한 기능은 작업 중복 방지, 역할별 권한, 처리 이력 관리입니다.

### 관리자 역할


| 역할             | 권한                             |
| -------------- | ------------------------------ |
| 소유자 (Owner)    | 전체 설정, 관리자 초대·해제, API 연결       |
| 운영 관리자 (Admin) | 해시태그·모니터링 계정 설정, 작업 배정         |
| 검토자 (Reviewer) | 팩트체크 결과 검토, 댓글 수정·복사, 게시 완료 처리 |
| 열람자 (Observer) | 대기 작업 및 검증 결과 조회               |


기존 잼통의 `admins/{uid}`는 문서의 존재만 확인하는 단순 관리자 체계입니다. 실제 `firestore.rules`와 `scripts/grant-admin.ts`에서 확인했습니다. 새 앱에서는 별도의 `fc_members/{uid}`에 역할과 활성 상태를 보관하겠습니다.

![](https://www.google.com/s2/favicons?domain=https://raw.githubusercontent.com&sz=32)

GitHub




| 판정      | 처리               |
| ------- | ---------------- |
| 사실      | 정정 댓글 불필요        |

데이터는 다음처럼 분리하겠습니다.


## 6. MVP 완성 조건

첫 버전의 검증 기준은 다음과 같습니다.

- A·B·C 중 어느 경로로 발견하더라도 같은 게시물이 중복 등록되지 않아야 합니다.
- Meta API 권한이 없더라도 제보 기능 C와 팩트체크 검토 큐는 정상 작동해야 합니다.
- AI는 본문을 확보하지 못한 게시물을 추측해서 판정하지 않아야 합니다.
- 잼통의 `CLAIM`을 별도 검증 없이 확정된 사실로 취급하지 않아야 합니다.
- 두 명의 관리자가 동시에 같은 작업을 수락할 수 없어야 합니다.
- 작업별 댓글 초안, 공식 출처, 수정 내역, 담당자, 수동 게시 완료 기록을 남겨야 합니다.
- 관리자 외 사용자는 검토 큐와 비공개 자료에 접근할 수 없어야 합니다.

GitHub를 연결하면 다음 개발 단계에서 저장소 파일을 직접 다루는 작업도 더 수월해집니다. 연결 전에도 공개 코드를 기준으로 설계와 구현 코드를 작성할 수 있습니다.
